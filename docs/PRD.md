# ModernTavern 产品需求文档

版本：0.1 · 更新日期：2026-10-19 · 状态：访谈收敛稿，尚未实现

本文记录本轮访谈已确认的产品决策，作为 MVP 设计与验收依据。未决事项明确列出，不将助手建议视为用户批准，也不将本次文档提交视为代码实施授权。后续决策变更应同步更新本文。

## 1. 产品目标

构建受 SillyTavern 启发的现代 RP 聊天产品，重点改善长文本阅读、文字输入输出、剧情控制和复杂功能的组织方式。

首版以用户本人的日常 RP 使用作为验收依据。产品采用 VPS + 浏览器、单用户自托管方式，支持多个设备同时登录，优先保证移动端浏览器体验。通过 Docker 简便部署，适合公网使用；不开发原生客户端。

视觉目标是现代、简洁、柔和且清晰；操作应避免误触生成、打断阅读或丢失输入。角色设定与外部文本之间的具体复制流程暂缓细化，MVP 先提供原始 Markdown 复制。

## 2. 范围与优先级

### 2.1 MVP 必须具备

- 原生聊天闭环：新建、打开、保存会话，发送消息、流式生成、停止、继续、重新生成。
- 消息编辑、删除及其明确的后续影响；最新 AI 回复的 Swipe 候选管理；显式独立分支。
- 后端持有生成任务，浏览器关闭或断线不取消生成；重连同步已保存内容与任务状态。
- 同一账号多设备同时登录；不同会话并行生成，同一会话最多一个生成任务。
- 多套 OpenAI 兼容连接配置的新增、编辑、删除、切换与模型选择。
- 阅读式与气泡式切换、多套主题配色、亮色／暗色／系统模式、字号和正文宽度设置。
- 移动端友好输入、阅读、浮框与操作入口。
- Docker 部署、首次设置单一账号密码、禁止开放注册。

### 2.2 后续阶段

- 角色卡、世界书、预设的管理与相关业务功能。
- SillyTavern 预设、世界书、聊天记录等文件的兼容导入导出。兼容是后续产品方向，具体版本、格式与保真范围尚未确定。
- 上下文容量由预设管理；MVP 暂用默认预算。

### 2.3 MVP 不纳入

- 原生客户端、多人账号服务、开放注册。
- 专门的角色／场景／系统提示词编辑入口；设定直接作为普通聊天消息发送。
- 滑动手势切换 Swipe、纯文本复制选项、自动故障重试。
- 未经确认的功能，例如原版 JS 扩展兼容、自动记忆、自动摘要、Agent 编排。它们不构成默认交付要求。

## 3. 核心概念

| 概念 | 产品语义 |
|---|---|
| 会话 | 一条有序的消息历史，可独立生成、命名和恢复阅读位置 |
| 消息 | 用户输入或 AI 回复；AI 消息可以持有多个候选 |
| Swipe 候选 | 同一 AI 消息的不同回复版本，保留当前选中状态 |
| 重新生成 | 为最新 AI 回复请求新候选，不覆盖或删除旧候选 |
| 继续 | 不发送新用户消息，沿当前剧情生成一条新的 AI 消息 |
| 分支 | 截至指定消息的完整独立副本，包含该消息及历史候选与选中状态 |
| 连接配置 | API 地址、凭据、模型选择等连接信息；不是 SillyTavern 预设 |
| 生成任务 | 后端管理的一次模型请求，不依赖浏览器连接存活 |

以上是行为定义，不规定数据库表结构或实现方式。

## 4. 会话、消息与剧情操作

### 4.1 消息和候选

- 只有最新 AI 回复可直接切换 Swipe 或请求新 Swipe；历史位置需要通过分支操作重新探索。
- 上一条／下一条按钮循环切换已有候选，不调用模型。新增候选仅通过独立的“重新生成”按钮触发。
- MVP 仅使用点击，不提供滑动手势。切到候选边界不能意外发起生成。
- 完整回复、主动停止和异常中断后的部分回复均保留；重新生成不会删除它们。
- 必须等后端确认上一生成已经完成或中断、不再输出后，才允许新生成。浏览器暂时没有收到文字不是完成证据。
- “继续”新增一条 AI 消息，上一条内容保持不变，不向原候选末尾追加文字。
- 模型上下文只采用当前剧情中选中的候选，不将其他候选重复加入。

### 4.2 编辑和删除

- 用户消息和 AI 历史消息均允许直接修订；提示后续内容不会重算，由用户判断剧情影响。
- 编辑采用原位文本框，保存后恢复显示。编辑会话不影响已经创建的独立分支。
- 多设备修改同一消息时采用最后保存覆盖，不引入强制冲突比较流程。
- 生成期间禁止修改当前会话上下文，该限制优先于最后保存覆盖规则。
- 删除历史消息会删除该消息及全部后续；执行前明确展示并确认删除范围。
- 候选单独删除、编辑取消后的草稿保留等细节仍待确定，不假设已经支持。

### 4.3 分支

- 用户主动选择“从这里分支”，创建新会话，原会话完整保留。
- 新会话包含分支点及之前所有消息、所有历史 Swipe 和各消息当前选中的候选。
- 分支具有 deep copy 使用语义：两边之后的编辑、删除、候选生成与选择互不影响；不要求物理复制每份存储。
- 例如在用户第 10 条消息上分支，新会话保留至该条；用户可编辑它后重新生成后续。
- 在 AI 消息上分支，该 AI 消息成为新会话末尾，可切换保留下来的候选或请求新候选。

### 4.4 名称、列表与阅读位置

- 默认名称：`会话 YYYY-MM-DD HH:MM:SS`；分支追加 `Branch #%d`。
- 名称时间的时区、分支编号计数范围与重命名入口尚未确定。
- 会话列表显示名称、最后时间、未读状态、正文结尾；正文结尾不是模型生成的摘要。
- “最后时间”的事件口径、结尾片段长度和未读清除时机待确定。
- 按设备保存阅读位置；切走再返回或刷新后恢复原位置，有新内容时提供回到底部入口。

## 5. 生成生命周期与多设备

### 5.1 必须满足的行为

- 生成由后端持有。关闭页面、切换会话或浏览器断网不直接取消模型请求。
- 恢复连接后同步已保存文本与最新任务状态；已完成的回复应可查看。
- 不同会话允许并行生成；同一会话只允许一个生成任务。
- 任一登录设备可查看同一会话的生成并发出停止请求。
- 生成期间所有设备均不能再次发送或修改该会话上下文；允许提前编辑未发送草稿。
- 主动停止后保留部分回复并标记已停止，下次发送时将其作为当前回复纳入上下文。
- 应用重启或供应商连接中断后，保留已收到的文本并标记中断，不自动续写或重试；用户手动决定后续操作。
- 不要求应用进程重启后恢复原供应商连接并无缝接着输出。
- 任务使用启动时配置快照；后续切换、编辑或删除连接配置不取消或改变已启动任务。

### 5.2 状态呈现

| 场景 | 界面行为 |
|---|---|
| 等待首字 | 在新 AI 消息处显示轻量动态圆点和“等待回复”，立即提供停止按钮 |
| 正在生成 | 仅更新当前生成内容，维持稳定排版；根据用户滚动状态决定是否跟随 |
| 主动停止 | 保留部分文本，明确标记已停止 |
| 生成异常 | 保留部分文本，标记中断并提供可理解的错误反馈，不自动重试 |
| 浏览器断线 | 持续显示不遮挡正文的“连接已断开，正在重连”，保留文本与草稿 |
| 连接恢复 | 自动同步内容和真实任务状态，不将断线误判为生成结束 |
| 其他会话完成 | 弹出可点击跳转的 toast，不自动切换当前会话 |

“停止请求已提交”与“后端任务已结束”需要区分；具体取消等待与失败反馈待交互细化。

### 5.3 状态保存范围

| 状态 | 范围 |
|---|---|
| 会话、消息、候选和任务状态 | 后端持久保存，各设备读取同一份状态 |
| 未发送草稿 | 各设备按会话分别保存，刷新和切换后可恢复，不互相覆盖 |
| 阅读位置 | 按设备分别保存 |
| 当前连接配置选中项 | 按设备独立，手机切换不改变电脑选中项 |
| 外观偏好 | 账号全局同步 |
| 系统亮暗模式 | 全局选择“系统”后，各设备跟随自己的系统状态 |

## 6. 模型连接与上下文

- MVP 支持 OpenAI 兼容接口；具体使用 Chat Completions、Responses 或其他协议边界尚未确认。
- 多套配置支持新增、编辑、删除、切换；每套记住最后选择的模型，作为该配置默认模型。
- 新生成使用当前设备选中的配置；当前模型选择在多端的同步语义仍需明确，不将“配置选中项独立”自动扩展为全部字段独立。
- API key 仅供后端调用使用，不进入前端持久存储、日志、导出文档或版本库；管理界面需要脱敏呈现。
- MVP 上下文容量默认 200K；未来由预设管理，不提前加入预设管理页面。
- 超出预算时自动省略最早消息，只发送最近能容纳的内容，并明确提示。完整聊天记录不删除。
- 用户接受早期普通消息中的角色设定也可能被省略；MVP 不默认固定设定或自动摘要。
- 200K 是应用预算，不是所有兼容模型的容量保证。单位、输入与输出预留、token 估算方式以及模型拒绝请求后的处理尚待技术设计。
- 模型列表获取与手动填写、输出上限、采样参数、超时与并发上限尚未确定。

## 7. 页面与 UI/UX

### 7.1 聊天布局与导航

- 默认仅显示聊天主体，没有常驻会话侧栏或模型设置右栏。
- 会话列表以浮框打开，不挤压正文；手机同样使用居中浮框，四周保留少量留白，列表内部滚动。
- 连接配置与模型统一在“连接”入口管理，不在顶部放置独立模型选择框。
- 连接面板的具体容器、顶部信息与其他入口位置尚未确定。

### 7.2 两种显示模式

| 模式 | 布局与用途 |
|---|---|
| 阅读式，默认 | 用户与 AI 卡片同宽、对齐，适合中文长篇 RP |
| 气泡式 | 用户靠右、AI 靠左，短消息收窄，长消息获得足够宽度 |

- 用户可切换模式，不改变消息内容与候选状态。
- 阅读式以同色系邻近底色区分用户与 AI；避免刺眼对比，也不能近似到难以分辨。
- 保留轻量身份标识，不仅依靠颜色表达来源。
- 长消息获得足够宽度不意味着默认折叠正文；是否需要折叠功能尚未讨论。

### 7.3 排版、主题与动效

- 提供舒适默认排版，仅开放字号与正文宽度调整，不增加行高、段间距或字体选择面板。
- 正文宽度必须受设备可用空间限制；全局同步设置不能造成手机横向溢出。
- 用户和 AI 内容使用标准 Markdown，动作描写采用斜体，控制标题与段落间距。
- 多套主题同时协调背景、卡片、边框和强调色；每套支持亮色、暗色、系统模式。
- 具体主题数量、配色值、默认亮暗模式与字体数值待视觉设计验证。
- 界面使用短过渡、淡入淡出和轻微位移，不采用弹跳或导致正文反复移动的动效。
- 保留键盘焦点、可访问名称和非颜色状态标识；减少动态效果偏好应受到尊重。

### 7.4 流式显示与滚动

- 提供直接显示和平滑显示，默认平滑；只缓冲少量文字，不做长时间逐字排队。
- 后端原始文本与前端显示进度分离，保存、复制、编辑与分支基于真实内容，不以动画进度为准。
- 用户主动上滑后停止自动跟随，显示回到底部入口；回到底部后恢复跟随。
- 流式 Markdown、频繁换段、斜体和长历史不应造成明显跳动或反复重排整个历史。

### 7.5 输入、编辑与操作栏

- 桌面 Enter 发送、Shift+Enter 换行；手机回车换行、点击发送。
- 中文输入法候选确认不能误触发送。
- 手机输入框随内容增高至有限高度，随后内部滚动；可展开为全屏写作。
- 原位编辑历史消息，提供明确保存／取消动作，保存后恢复正文。
- 复制按钮仅复制原始 Markdown；MVP 不增加纯文本复制方式。
- 手机消息轻量操作栏直接显示复制与更多；最新 AI 回复另外显示候选切换与重新生成。
- 更多操作承载编辑、分支和删除等能力，具体顺序与桌面显隐方式待细化。

## 8. 部署与运行要求

- Docker 部署，面向 VPS 与浏览器访问，提供可验证的启动与持久数据配置说明。
- 首次部署设置单一账号密码，不开放注册；支持多个设备同时保持登录。
- 公网使用需完成应用认证与 HTTPS 部署路径；反向代理、证书接入与首次初始化方式待技术设计。
- 认证前不得暴露会话、任务或连接凭据；凭据不得写入仓库或明文日志。
- 部署更新和重启不得丢失已保存会话；对执行中的任务需要恢复为准确的可理解状态。
- 持久卷、备份恢复、认证会话有效期、密码重置和退出范围待确定。

## 9. 技术约束与待验证选型

用户指定前端基础为 [nuxt-shadcn-dashboard](https://github.com/dianprata/nuxt-shadcn-dashboard)。实施前核对实际版本、依赖和许可证；本轮未进行代码或版本核验。

- 模板用于组件、设计系统和应用外壳，不将演示登录页或持久化依赖视为完成的业务能力。
- 优先复用现有框架和组件，采用 UI Library First、Theme First、CSS Last；不为模仿视觉参考引入重叠 UI 框架。
- Apple HIG、Primer／Radix Themes、Ant Design 仅作交互与设计参考，不构成依赖要求。
- Nuxt Nitro 或 FastAPI、数据库、任务持久化、流式协议、SDK、Pinia 职责边界均尚未最终选定。
- Fetch + SSE、markstream-vue、streamdown-vue、AI SDK 等属于先前候选，不是已批准技术基线。
- 选型需验证后台持续生成、断线恢复、多会话并行与移动端长文本体验，不能只以简单聊天演示作为依据。

## 10. MVP 验收场景

以下是待执行的验收条件，不表示已经实现或通过。

| 编号 | 场景 | 通过条件 |
|---|---|---|
| AC01 | VPS 首次部署与登录 | 可按文档启动、初始化单账号；未登录不能访问业务数据，多设备能同时登录 |
| AC02 | 浏览器关闭与断线 | 生成不因浏览器离开被取消；重新打开可见完整或明确中断的回复 |
| AC03 | 应用／供应商故障 | 已接收内容按明确的持久化保证保留，状态不永久停在生成中，不自动产生收费重试 |
| AC04 | 多端与并发 | 不同会话并行；同一会话重复请求被阻止；任一设备可停止；生成中禁止修改上下文 |
| AC05 | Swipe | 按钮循环切换不请求模型；独立重新生成新增候选，旧候选含部分回复仍保留 |
| AC06 | 继续 | 不新增用户消息即可生成下一条 AI 消息，原回复不被追加或替换 |
| AC07 | 分支隔离 | 包含分支点及所有历史候选和选中状态；修改任一会话不改变另一会话 |
| AC08 | 编辑与删除 | 原位编辑保留后续；多端最后保存覆盖；删除先确认并移除该点及后续 |
| AC09 | 多配置 | 支持配置管理与默认模型记忆；设备选中项独立；进行中的任务不受配置变更影响 |
| AC10 | 上下文裁剪 | 超预算时省略最早内容并提示；数据库历史完整；供应商超限有明确错误反馈 |
| AC11 | 长文阅读 | 两种模式可切换，身份可区分；中文长文、Markdown 与频繁换段排版稳定 |
| AC12 | 阅读位置与草稿 | 上滑不被拉回；切换／刷新恢复位置和设备草稿；其他设备不覆盖本地草稿 |
| AC13 | 手机输入与复制 | 软键盘下可输入、换行、发送、全屏写作；原位编辑可用；复制保持原始 Markdown |
| AC14 | 外观与导航 | 偏好跨设备同步且适配窄屏；浮框不溢出；列表显示名称、时间、未读及正文结尾 |
| AC15 | 状态反馈 | 首字等待可停止；后台会话完成 toast 可跳转；断线提示不遮挡正文且重连能同步 |
| AC16 | 持久化与更新 | 重启后已有会话、候选、分支和配置不丢失；中断任务状态可恢复 |

验收使用真实桌面与手机浏览器，覆盖键盘、焦点、弹层、加载、错误、重连、中文输入法和长文本。具体浏览器矩阵、长历史规模、性能指标与故障持久化容忍范围需在实施计划前补齐。类型检查、单元测试、构建、后端验证与浏览器实测分别报告，不能互相替代。

## 11. 未决事项与下一步

### 实施前需要解决

1. 兼容接口协议、模型列表和参数范围；200K 的精确定义、token 计算与输出预留。
2. 后端、数据库、任务生命周期、增量保存与恢复方案；故障时文本持久性承诺。
3. 首次账号初始化、HTTPS 接入、凭据保护、备份恢复与 Docker 交付结构。
4. 多端最后模型选择的同步范围；已选配置被另一设备删除后的反馈。
5. “最新 AI 回复”在末尾存在未获回复的用户消息时的准确边界；空输出故障与取消处理。
6. 分支名称时间、时区及编号范围；会话排序、未读清除和正文结尾截取规则。

### 交互细化阶段需要解决

- 连接管理浮层、设置入口、桌面消息操作栏、搜索／重命名／会话删除是否纳入 MVP。
- 消息编辑未保存时跳转、点击完成 toast 时的处理，以及草稿保存提示。
- 单独候选删除、生成中切换旧候选、分支操作的开放时机。
- 错误重试入口、取消请求等待状态、无输出任务的占位消息处理。
- 主题数量与色值、字号及宽度范围、浮框焦点与返回行为。

下一步建议先解决架构阻塞项，再通过交互原型验证关键屏幕，最后形成分批实施计划。这是后续工作建议，尚不代表开发排期或实施授权。
